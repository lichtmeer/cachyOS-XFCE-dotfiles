# Conky 1.25.2 mouse-event regression: diagnosis + downgrade

## Symptom
The widget's transport buttons (prev / pause / next) silently stopped
working on 2026-10-13, ~30 min after a routine system update upgraded
conky 1.24.2 -> 1.25.2.

## Diagnosis chain
1. playerctl + spotify: perfectly healthy (widget could draw, buttons dead)
2. Synthetic clicks at verified button coordinates: no effect
3. Injected event logger in the lua_mouse_hook: ZERO events received -
   conky never delivered a single mouse event to the hook
4. Window-config battery (normal/below-less/dock/desktop/override):
   ONLY override received events - proving the hook and Lua code were fine
   and the regression was in event delivery for 'normal' undecorated windows
5. Upstream source (conky master, x11.cc): the #2451/#2454 fix installs an
   empty XShape input region (full click-through) on undecorated non-override
   windows - side effect: conky never sees clicks anymore on exactly our setup
6. own_window_input_from_alpha (upstream's intended interactive-window path):
   tested, delivered zero events on the 1.25.2 build - abandoned

## Fix
Downgraded conky to the cached known-good package:
  sudo pacman -U /var/cache/pacman/pkg/conky-1.24.2-*.pkg.tar.zst
and pinned it (IgnorePkg = conky in /etc/pacman.conf) until upstream fixes
the regression. No config changes were needed - the repo config is already
the correct, working one.

## Un-pin procedure (when upstream fixes it)
Remove the IgnorePkg = conky line from /etc/pacman.conf, then pacman -Syu.

## Lessons
- The event logger (temporarily injected into glance.lua) was the decisive
  diagnostic: it proved the hook receives zero events, pointing at delivery
  instead of our Lua.
- Zero config changes survived this fix; everything is as committed.
