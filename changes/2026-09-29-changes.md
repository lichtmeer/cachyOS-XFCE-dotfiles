# Report 2026-09-29: Rofi window switcher (Super+Tab)

## What we built today

A window switcher that matches the launcher, plus a transparency
experiment that was rolled back by popular demand.

1. **Rofi window switcher** - `rofi -show window -theme window`, bound
   to Super+Tab. Same Material You pill as the app launcher: 480px,
   #1C1B1F surface, #A4C3FF accent, YAMIS icons, blue rounded
   selection frame. Lists every open window with its workspace
   number; type to filter, Enter to switch, Escape to cancel.
2. **Cycling inside the switcher** - Alt+Tab walks down the list,
   Alt+Shift+Tab walks back up (kb-row-down / kb-row-up in
   window.rasi). XFCE's own Alt+Tab switcher still works when rofi
   is closed; rofi grabs the keyboard while open, so the keys must
   be bound inside rofi to have any effect there.
3. **Transparency experiment (rolled back)** - briefly set
   active/inactive window opacity to 0.90 with fullscreen solid.
   Removed again the same day: the see-through look was not wanted.
   picom.conf is back to its previous state (no opacity lines).

## Where the files are

| File | What it is |
|---|---|
| rofi/window.rasi | Window switcher theme (config + colors + layout) |
| rofi/config.rasi | "window" added to the modi list |
| ~/.config/rofi/window.rasi | Live copy of the theme |
| ~/.config/rofi/config.rasi | Live config, "window,drun" modi |

## Settings that live outside files (not in the repo)

- Keyboard shortcut Super+Tab -> `rofi -show window -theme window`,
  stored in xfce4-keyboard-shortcuts (xfconf). Re-add on a fresh
  install via Settings -> Keyboard -> Application Shortcuts, or:
      xfconf-query -c xfce4-keyboard-shortcuts \
        -p "/custom-keyboards/custom-Super-Tab" -n -t string \
        -s "rofi -show window -theme window"

## Bugs found and fixed along the way (worth remembering)

- Rofi rejected our kb-row-down/kb-row-up bindings with "Binding
  'Control+j'/'Control+b' already bound": newer rofi already binds
  Ctrl+j/Ctrl/k for list movement by default. Fix: declare only
  Alt+Tab/Alt+Shift+Tab; the arrows and Ctrl+j/k keep working via
  rofi's own defaults.
- `picom --replace` does not exist in picom v13 (option removed).
  Restart with `killall picom; sleep 1; picom -b` - the sleep matters:
  without it the new picom races the old one shutting down and dies
  with "Another composite manager is already running".
- Pasting multi-line heredoc blocks into the terminal scrambled the
  paste twice (lines merged/repeat-pasted), producing broken config
  files. Long terminal pastes are fragile; a single-line base64
  pipe (`echo <b64> | base64 -d > file`) is paste-proof.
- `rofi ... | head -5` silently kills rofi via the closed pipe;
  run rofi plainly or with `tee` to a log file when debugging.

## How to debug rofi (for future us)

- Run `rofi -show window -theme window` from a terminal: errors and
  binding conflicts print on startup.
- `rofi -keybindings` lists all configurable bindings - check for
  duplicates before declaring your own.
- `--log-file /tmp/rofi.log` + `-log-level debug` for more detail.

## Known caveats

- Rofi window mode is filter-and-pick, not hold-and-cycle: Alt+Tab
  inside rofi moves the selection, Enter switches. Instant
  hold-Alt-tap-Tab cycling stays with XFCE's own switcher.
- If rofi is ever rebuilt without window mode support, `-show window`
  fails; standard Arch builds include it.

## Removal (if we ever want it back to plain)

    rm ~/.config/rofi/window.rasi
    sed -i 's/modi: *"window,drun"/modi: "drun"/' ~/.config/rofi/config.rasi
    xfconf-query -c xfce4-keyboard-shortcuts \
      -p "/custom-keyboards/custom-Super-Tab" -r || true
