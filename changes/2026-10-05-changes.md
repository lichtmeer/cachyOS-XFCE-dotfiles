# Report 2026-10-05: weather localization — right city, no personal data in the repo

## What we built today

The weather showed the wrong city: wttr.in was asked without a location, so it
guessed from the server-side IP of the request, which landed in the right
country but the wrong place. This session made the widget ask for the right
location without putting anything personal into the repo.

1. **Why "Overcast" looked wrong** — the description itself was fine, but it
   described a city ~200 km away. Cause: `weather.sh` called
   `wttr.in/?format=...` with an empty location, so wttr.in picked a location
   itself from the connection's IP.

2. **Postal code attempt, then removed** — pinning by postal code worked
   (wttr.in accepts them), but a postal code is personal data and this is a
   public repo. It was removed from all committed files before pushing.

3. **Final design — three layers, nothing committed**:
   - `$1` argument to `weather.sh` (manual override, not stored anywhere)
   - `~/.config/conky/location` — a local-only file with one line (city or
     postal code). It lives outside the repo and is never committed.
   - If neither exists: IP-based localization via `curl
     https://ipinfo.io/city` (or wttr.in's automatic guess as last resort),
     so a fresh install still shows a nearby city out of the box.

## Where the files are

| File | What it is |
|---|---|
| `conky/weather.sh` | wttr.in fetcher; reads `$1`, then `~/.config/conky/location`, then IP fallback |
| `~/.config/conky/location` | local-only location (NOT in repo, never committed) |

## Addendum: autostart black-box fix (same day, after reboot)

### Symptom

After a reboot the widget background was solid black instead of
transparent. Restarting conky manually fixed it every time.

### Root causes (two, stacked)

1. **Boot race** — conky started before picom had the compositor ready
   (conky PID was lower than picom's). A transparent conky window with
   no compositor running renders its background as black.
2. **Duplicate autostart entry** — `~/.config/autostart/` contained both
   `Conky glance.desktop` (from the installer) and `conky.desktop`
   (added manually via XFCE settings). Two conky instances drew on top
   of each other; the unfixed one was the black box.

### Fix

- Removed the manually added `conky.desktop` (via XFCE settings GUI).
  Side effect: the GUI also marked the remaining entry disabled
  (`Hidden=true`), so the widget briefly stopped starting at all.
- Rewrote `Conky glance.desktop` with:
  - `Hidden=false` (re-enabled)
  - `Exec=sh -c "while ! pgrep picom >/dev/null; do sleep 0.5; done;
    sleep 0.5; conky -c ~/.config/conky/conky.conf"` — waits for picom
    instead of a blind sleep, then starts conky.

### Lesson

The XFCE autostart GUI is just a viewer for `~/.config/autostart/*.desktop`;
"disabled" is stored as `Hidden=true` inside the file. When a widget dies
after GUI changes, check the file, not just the checkbox. And when a
transparent widget turns black only at boot, check process start order —
transparency needs the compositor alive *before* the window is created.
