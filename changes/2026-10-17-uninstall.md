# 2026-10-17: Install is fully reversible (backup + uninstall.sh)

- install.sh now makes a backup of everything it replaces on its FIRST run only, kept in ~/.local/share/cachyos-dotfiles-backup: every config file about to be overwritten (polybar, rofi, picom, alacritty, fastfetch, conky, plank, autostart entries), the YAMIS icon directory (as a tar), and the current value of every xfconf setting it changes. Re-runs keep the original backup untouched, so the revert always goes back to the true pre-desktop state.
- New uninstall.sh: restores every backed-up file, deletes files the installer created where nothing existed before, restores saved xfconf values (or resets them to factory default when none existed), re-enables the stock XFCE panel and compositor, and offers to revert the system-level changes (udev backlight rule, LightDM greeter theme lines, video group membership) and optionally the packages. Personal files (wallpapers, weather location) are never touched. Ends with a logout offer, like install.sh.
- Found and fixed during testing: the autostart entries are enumerated from the repo (a glob of existing files would have missed the ones the installer creates new), the YAMIS tar is extracted into ~/.icons (it was created inside it), and files with spaces in their names (e.g. "Conky glance.desktop") back up and restore correctly.
- Sandbox-tested with stub tools, running the exact delivery command end-to-end from a fresh clone: fresh install on a customized machine (pre-existing configs + xfconf values) -> backup complete; install run twice -> backup untouched; uninstall -> all 17 checks pass (files restored, new files removed, untouched files survive, xfconf values restored, created props reset to factory, wallpaper restored). uninstall without a backup prints a clean nothing-to-revert message.
- Docs: README install section mentions the backup + uninstall.sh; INSTALL.md rollback section rewritten around uninstall.sh.
